# Phaser MMO performance and legacy-flow audit

Audit date: 2026-10-26 (Asia/Ho_Chi_Minh)  
Scope: checked-out frontend/backend source, MMO design and release docs, and the user-provided system-monitor screenshot. The initial pass was static/code audit plus existing local checks, not a production load test. A browser follow-up reproduced a stale realtime connection and added a client recovery guard; no load-capacity claims are made.

> **Working-tree follow-up:** the unused `GET /api/merchant/map` route, store state/poll, and `GET /api/explore/players` route were removed after this audit found no current frontend consumer. This removes stale-request overhead but does not establish or fix the cause of movement stutter. Historical measurements and code references below describe the audit checkout before this follow-up. External or older clients calling the removed routes will receive 404.

> **Movement follow-up:** in the open Phaser browser tab, F3 showed 106 FPS while the authoritative tick stayed at 32683, snapshot count at 692, and age of the latest WebSocket message grew from about 92 s to 129 s. A directional input and click-to-move did not advance the tick. Since the server runs active zones at 20 Hz, this is direct evidence of a silent/half-open realtime connection, not a render frame-rate bottleneck in that session. `WorldRuntime` now reconnects when an active joined socket has received no world snapshot for 3 s, with bounded retry spacing; WebSocket join now times out after 10 s so it cannot remain connecting forever. Failed rejoin transitions to the existing error/retry UI. The browser then remained on its prior build's connecting screen for over 11 s; its console showed an expired authorization token and API timeouts, so the edited reconnect path still needs verification after restarting the app with a valid session and backend.

## Executive summary

Phaser is the default world surface in the checked-out frontend (`useUIStore.currentView = "mmo-world"`, rendered through `PhaserWorldHost`). A live authoritative zone still depends on the public map/content version configuration and backend admission; without those values the host renders preview mode. The current code is therefore Phaser-first at the UI entry point, while live MMO admission and several gameplay integrations remain gated or incomplete.

The clearest measured server optimization target is snapshot allocation. The synthetic 100-player/50-mob benchmark records 1.46 ms p99 `Step` time but about 1.14 GB allocated over 1,000 ticks (~1.1 MB/tick). In the direct browser follow-up, F3 reported 106 FPS while snapshot delivery was stalled for over two minutes; this identifies a realtime transport failure in that session, but does not provide frame-time percentiles or capacity data. Client entity-view allocations remain a separate unmeasured optimization candidate.

The screenshot reports 3,809 requests, 1.98 requests/s, p50 2.88 ms, p90 23.35 ms and p99 115.95 ms. It highlights slow `POST /api/player/notifications/read-all` (10 requests, 1 error, 1,504 ms average, 15,003 ms max), errors on `GET /api/merchant/map` (29/327) and `POST /api/inventory/use-gu` (65/97), and frequent nearby-player/spatial-realm/merchant reads. Those are observations from the last 500-request view, not a dated production baseline or Phaser QoS measurement. The monitor's `error_count` counts every HTTP status >=400, including expected 4xx responses.

## Findings and recommendations

| Priority | Finding and evidence | Recommended action and success evidence |
| --- | --- | --- |
| P1 | **Snapshot copying is the clearest measured server cost.** `sim.World.Step` calls `publish`; `publish` copies and sorts all entities, materializes projectiles/events, stores the snapshot and returns another detached copy (`backend/internal/realtime/sim/world.go:571, 869-927`). Synthetic measurements in `docs/mmo/benchmark.md` show low tick CPU time but high allocation volume. | Profile allocations at 5/30/100 real clients, then reduce avoidable copies/sorts while preserving immutable snapshots for concurrent readers. Compare allocation bytes/tick, GC pause/CPU and tick p95/p99 against the same recorded workload. |
| P1 | **The Phaser render path creates per-frame entity objects.** `WorldScene.update` calls `getEntities` every frame (`frontend/src/game/scenes/WorldScene.ts:303-332`); `WorldRuntime.getEntities` allocates an array and a presentation/entity object for every visible entity (`frontend/src/game/core/WorldRuntime.ts:292-320`). `syncActors` also constructs a `Set` and scans for self each frame (`WorldScene.ts:1051+`). | Record browser frame-time and allocation profiles with representative AOI sizes before optimizing. Reuse stable entity views/iteration state only if profiling confirms this path is material; preserve Phaser actor updates and React HUD cadence. |
| P1 | **Dynamic world overlays are rebuilt on a timer.** Every 800 ms `syncDynamicWorldObjects` clears the Graphics object, destroys all labels, and recreates marker graphics/text (`WorldScene.ts:926-960`, continuing through 1048). | Cache marker output by relevant data revision, update changed markers, and avoid off-camera labels where measurements show benefit. Validate frame-time spikes and heap/GC during dense marker scenes. |
| P1 | **AOI fan-out and per-socket encoding need real-client profiling.** `Manager.broadcastSnapshots` rebuilds a spatial index for each received zone snapshot, queries every subscriber and pushes feeds while holding `m.mu` (`backend/internal/realtime/world/manager.go:1026-1070`). Each socket then builds a delta and marshals JSON (`backend/internal/ws/client.go:651+`). Queue depth, AOI bytes and serialization time are not currently measured. | Add per-zone and per-client measurements, then evaluate index reuse and lock-scope reduction. At 5/30/100 clients capture queue depth/drop/resync, AOI bytes/client, serialization duration and input-to-ack latency. |
| P1 | **Snapshot coalescing can drop event batches under backpressure.** Snapshot feeds replace an older queued snapshot, which is appropriate for state convergence; `sendWorldEvents` drops a batch when the send queue is full and reliable replay is not implemented (`backend/internal/ws/client.go:651+`; `docs/mmo/protocol-v1.md`). | Keep snapshots coalescible, but add event acknowledgement/replay or an explicit resync/recovery contract for gameplay-critical events. Verify combat feedback, death and loot behavior under slow-client, reconnect and queue-saturation scenarios. |
| P1 | **The merchant marker poll is both wasteful and incompatible with realtime ownership.** The root world view calls `fetchMerchantMarkers` immediately and every 30 seconds (`frontend/src/app/page.tsx:236-248`). That calls `/api/merchant/map` (`frontend/src/store/slices/inventorySlice.ts:377-389`), whose route applies `RequireLegacyWorldMode`; the middleware returns 409 when the realtime runtime owns the character (`backend/internal/server/server.go:971-979`, `backend/internal/middleware/realtime_world.go:81-98`). `merchantMarkers` has no other frontend consumer in this checkout. This is a strong code-based explanation for some of the screenshot's 29 errors, but the request trace status is needed to confirm. | Remove the unused polling/state path if no external client depends on it, or deliberately replace it with realtime-compatible marker data if the map feature is still wanted. Confirm a realtime-owned session no longer generates these 409s and merchant trading still works through its business endpoints. |
| P1 | **Nearby-player traffic in the screenshot has no caller in the checked-out frontend.** `/api/explore/players` is backed by `worldPosIndex.NearbyInScope` with SQL fallback (`backend/internal/handlers/exploration_views.go:174-262`), but repository search finds only its route/docs, not a frontend request. | Check deployed frontend version, browser network initiator and other clients before optimizing this handler. Remove stale callers or document an external consumer; do not attribute its request volume to current Phaser without evidence. |
| P1 | **`inventory/use-gu` needs error-reason and ownership-contract review.** The handler is a consumable-Gu business action, opens a DB transaction and bridges HP changes into realtime (`backend/internal/handlers/player_gu_use.go:21-47, 200`). Its route is not guarded by `RequireLegacyWorldMode` (`backend/internal/server/server.go:675-685`), so the 65/97 screenshot errors are not explained by the known legacy-mode 409 guard. | Inspect representative failed request traces by HTTP status, response reason, player/session mode and Gu state. Decide which consumable effects are safe while a character is zone-owned, and test that DB state, live entity vitals and client inventory converge after success/failure. |
| P1 | **The 15-second notification outlier matches the configured database statement timeout.** `MarkAllNotificationsRead` updates every unread row for the player (`backend/internal/handlers/notifications.go:107-120`); an unread partial index exists (`backend/internal/db/schema_social.go:159-165`). Database defaults include `statement_timeout=15000ms` and `lock_timeout=10000ms` (`backend/internal/db/db.go:139-145`). The screenshot maximum is 15,003 ms. | Inspect the failed trace and staging/production `pg_stat_activity`, wait event/lock chain, per-player unread row count and dead tuples before changing SQL or indexes. Pass when the cause is identified and a repeat workload no longer reaches statement timeout. The existing index means an absent index is not the leading hypothesis. |
| P2 | **Cell reads can complete out of order and overwrite a newer area.** The Phaser HUD polls cells every 30 seconds and refreshes after harvest (`frontend/src/components/game/MMOHud.tsx:290-317`; `frontend/src/store/useWorldStore.ts:48-90, 101-105`). There is no request dedupe, abort or coordinate-key guard before `set({ nearbyCells })`. The socket command is preferred, with HTTP fallback. | Use an area/zone key with in-flight dedupe and latest-request-wins, refresh on area transitions, pause while hidden, and keep HTTP fallback only for supported degraded states. Test movement across area boundaries with delayed/out-of-order responses and a failed WebSocket request. |
| P2 | **The active spatial-realm poller is not mounted in this checkout.** `SpatialRealmHUD` polls `/api/spatial-realms/active` every 20 seconds (`frontend/src/components/SpatialRealmHUD.tsx:7-25`), but repository search finds no render site. The endpoint runs a DB join and correlated member count (`backend/internal/handlers/spatial_realms.go:130+`). This may explain screenshot traffic only if an older/deployed client still mounts it. | Verify the deployed bundle and request initiator. Remove the dead component/poll path if unused, or mount it intentionally and make its refresh lifecycle visible/appropriate for Phaser. Avoid query optimization until a live caller and DB cost are confirmed. |
| P2 | **Monitor middleware adds request work and retains response content.** It reads/replays JSON request bodies, wraps response writers and records request/response bodies for every non-OPTIONS request (`backend/internal/monitor/monitor.go:190-218, 672-740`). Request JSON is redacted; the response capture path does not apply equivalent redaction. This work is global (`backend/internal/server/server.go:402`). | Keep lightweight counters/latency always on; sample body capture or limit it to slow/error traces, exclude streams, and redact response fields. Measure middleware overhead under representative request rates and add a redaction review before retaining traces. |
| P2 | **Legacy batch persistence has unbounded flush input and weak backlog visibility.** `GetPendingIDs` uses `SMEMBERS` for the complete pending set (`backend/internal/cache/redis.go:222-228`); `flushEntityType` materializes all IDs/payloads and processes entity types serially (`backend/internal/worker/batch_persister.go:43-90`). Queue depth is a single overwritten gauge, with no oldest-age/flush-duration metric; shutdown flush uses `context.Background()` without a bound (`:21-40`). | Bound and measure persistence batches, record backlog age/duration/failure and degraded Redis state, and bound shutdown flush time. Preserve the existing compare-and-ack/data-integrity semantics. This is shared operational debt; confirm whether it handles MMO-critical state before prioritizing against Phaser work. |
| P2 | **Horizontal zone scaling is not safe to infer from in-process capacity.** Manager ownership is process-local; cross-process lease fencing, gateway routing and split-brain recovery remain open (`docs/mmo/scaling.md`, `docs/mmo/remaining-limitations.md`). The current SLOs for tick, queues, input-to-ack, AOI bandwidth and client FPS are candidate targets, not measured gates (`docs/mmo/slo.md`). | Keep admission conservative until browser/network load, cross-process ownership fencing, duplicate-loot replay and recovery evidence exist. Do not increase zone capacity based only on synthetic CPU timing. |
| P3 | **Active MMO panels use broad Zustand subscriptions.** `MMOBusinessPanels` and `MMOSettingsPanel` call `useGameStore()` without selectors (`frontend/src/components/game/MMOBusinessPanels.tsx:31-35`, `MMOSettingsPanel.tsx:61-69`). `PhaserWorldHost` already limits React HUD projection to about 10 Hz (`:217-229`), which helps keep simulation rendering out of React. | Profile React commits with chat/player events and open panels; replace whole-store subscriptions with focused selectors where they cause measured commits. Keep high-frequency entity state in the Phaser runtime rather than publishing it through Zustand. |

## Legacy flow disposition

This is an in-repository consumer audit. It cannot establish whether a route is used by an external script, an older deployed client or a mobile client.

| Legacy subsystem | Current evidence | Disposition |
| --- | --- | --- |
| Legacy world-map rendering and movement UI | `WorldPage`, `WorldCanvas` and `ExplorationMap` are absent from `frontend/src`; current `mmo-world` renders `PhaserWorldHost` (`frontend/src/app/page.tsx:357-390`). Older `legacy-flow.md` still describes the old default and is stale against current source. | **Removed from active UI; retain backend compatibility temporarily.** Before deleting routes/workers, search external clients and complete the character mutation/ownership audit plus rollback rehearsal. Update stale docs with the current checked-out flow. |
| Turn-based exploration/combat handlers and simulator | Store slices still call `/api/explore`, `/api/combat/start`, retreat/flee and combat history; `CombatScreen` is still mounted when `player.active_combat` is set (`frontend/src/app/page.tsx:377-386`; `frontend/src/store/slices/combatSlice.ts`). | **Transfer combat/movement authority to Phaser; keep as fallback until parity and rollback gates pass.** Define resolution for existing active combats and prove all mutations reject or safely reconcile while realtime owns the character. Retire turn-based simulation only after no active UI/API consumer remains. |
| World cell/nearby APIs | Phaser asks `world.cells_rect` over the shared socket and falls back to `/api/explore/cells/rect` (`frontend/src/store/useWorldStore.ts:55-70`; `backend/internal/handlers/world_ws.go`). Nearby player endpoint has no in-repo frontend caller. | **Keep cell fallback during transition; retire unused nearby-player endpoint after external-consumer check.** Reduce cell polling/stale writes and make the realtime command the normal path. |
| Merchant marker map | Frontend polls `/api/merchant/map` but no frontend code reads `merchantMarkers`; route rejects realtime-owned characters. | **Remove unused poll and store state; route is an endpoint-removal candidate after external-consumer check.** Keep `/api/merchant`, quote, buy and sell as business operations if Phaser still exposes roaming-merchant trading. |
| Consumable Gu and inventory/progression mutations | `/api/inventory/use-gu` remains an active business action and has a realtime HP bridge; inventory, Gu, cultivation and progression panels are rendered inside Phaser. | **Keep shared domain APIs; audit and complete realtime-state synchronization.** Do not remove these with old world movement/combat. Keep active Gu combat casts on the Phaser protocol. |
| Sect, party, trade, chat, notifications, markets, quests and administration | Existing Zustand slices and API routes serve non-world business/social features integrated into the Phaser shell. | **Keep as shared services/UI.** Migrate only world-presence or combat actions that still assume legacy coordinates/ownership. |
| Spatial realm HUD | Polling component exists but has no render consumer in this checkout; realm entry/exit API still exists. | **Remove the unmounted HUD/poll if no product entry point needs it; otherwise integrate it deliberately with Phaser.** Retain realm domain handlers while the feature remains supported. |
| Legacy monster workers and reward paths | Old handlers/workers coexist with realtime death processing. Realtime loot currently auto-grants idempotently; ground-drop/corpse interaction and several party loot behaviors remain incomplete (`docs/mmo/remaining-limitations.md`). | **Keep legacy reward paths until realtime parity and exactly-once staging replay pass.** Then remove paths only after proving no legacy-owned character or client can still invoke them. |

## Measurement plan

Run the same staged configuration and record commit/build hash, machine/container limits, browser/GPU, map/content hashes, database/Redis versions and network profile. At 5, 30 and 100 real clients, collect:

- Client frame-time p50/p95/p99, long tasks, heap/GC, draw calls and visible entity/marker counts.
- Server zone tick p95/p99/p99.9, entity/player counts, input-to-ack, AOI bytes/client, JSON encode duration, outbound queue depth, drop/resync count and reconnect outcomes.
- PostgreSQL pool wait, query/lock wait, slow query/status, and Redis pool/degraded state plus persistence backlog age/flush duration.
- Combat and economy integrity: duplicate event/loot grants, stale inventory or vitals, reconnect/transfer ownership and checkpoint recovery.

Use the candidate thresholds and measurement protocol in `docs/mmo/slo.md`; current values are not evidence of a pass. Test network profiles with latency, jitter and packet loss and include slow-client/backpressure, DB lock/timeout, Redis disconnect, reconnect during combat, and repeated death/loot replay. Keep production admission/capacity limited until staging evidence and rollback rehearsal close the open gates.

- `docs/mmo/legacy-flow.md` and the opening of `docs/mmo/rollout.md` describe the legacy world as default, while current `useUIStore` defaults to `mmo-world` and `page.tsx` renders Phaser there. Reconcile these docs with the exact current flag/config behavior.

- Keep the central limitations from `docs/mmo/slo.md` and `docs/mmo/remaining-limitations.md`: real-browser/network capacity, database/Redis load, cross-process ownership, complete event replay and staging rollback are still unproven.

Problem

Two full copies of the same resolution flow stay in sync by comment, and the skip-battle copy re-derives the winner by matching a localized log string.

Solution

Collapse the shared outcome into one module whose interface is "snapshot + mode in, persisted result + logs out"; callers keep only their own preconditions.

Problem

Transport is centralized, but every slice re-implements the same ok-check, error toast, and request dedup; the intended wrapper (apiFetch) is dead code, and the sparse-inventory merge is duplicated between two root helpers.

Solution

Wire apiFetch (or a small gameClient) as the single interface slices call; its implementation owns ok-check, toast, and dedup.

Wins

  • ~200 ok-checks collapse
  • dedup stops drifting per slice
  • one place to change error policy

Top recommendation

One combat outcome, two implementations

It is the highest-churn, highest-risk area: two parallel resolution flows kept aligned by comments, a second legacy engine living inside Flee, a winner decided by matching Vietnamese log text, and the coordination layer that actually breaks has almost no tests. Deepening it concentrates loot, defeat, and persistence behind one interface — and every other candidate gets cheaper once combat stops duplicating itself.
